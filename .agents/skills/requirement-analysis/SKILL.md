# 요구사항 분석 스킬

Lootwise 기능 요청이 모호하거나 구현 가능한 수준으로 정리가 필요할 때 이 스킬을 사용합니다.

항상 repository 루트의 `AGENTS.md` 규칙을 따릅니다.

## 프로젝트 컨텍스트

- 프로젝트: lootwise
- 도메인: Steam 게임 할인, 가격, 관심 게임, 시세 정보, 알림, 랭킹
- 백엔드: Kotlin, Spring Boot
- DB: PostgreSQL

## 역할

- 구현 전에 기능 목표를 명확히 정리합니다.
- 모호한 요청을 백엔드 개발 요구사항으로 변환합니다.
- 도메인 정책, 예외 케이스, 모호한 점을 식별합니다.
- 이후 설계에서 Controller에 비즈니스 로직이 들어가지 않도록 범위를 나눕니다.

## 출력 형식

### 기능 목표

- 기능의 목적을 한두 문장으로 구체적으로 작성합니다.

### 사용자 시나리오

- 주요 사용자 흐름을 작성합니다.
- 가격 수집, 알림 발송처럼 시스템이 자동으로 수행하는 흐름도 필요하면 포함합니다.

### 정책

- 비즈니스 규칙을 정의합니다.
- Steam 데이터 전제, 가격 갱신 시점, 중복 처리, 공개 범위 규칙이 필요하면 포함합니다.

### 예외 케이스

- 잘못된 입력, Steam 데이터 누락, 외부 API 장애, 중복 데이터, 권한 또는 소유권 문제를 정리합니다.

### 모호한 점

- 구현 전에 확인해야 할 질문을 정리합니다.
- 반드시 확인해야 하는 질문과 가정해도 되는 내용을 구분합니다.

### 백엔드 영향 범위

- 영향을 받는 도메인, Service, Adapter, API, DB 테이블, 스케줄러, 테스트를 식별합니다.

### 우선순위

- MVP, 후속 작업, 선택 개선 사항으로 나눕니다.

## 규칙

- 이 스킬만으로 구현 코드를 작성하지 않습니다.
- 요구사항에 Steam API 또는 크롤링이 포함되면 adapter 경계를 명확히 표시합니다.
- nullable 처리와 소유권 규칙은 명시적으로 정리합니다.
- 이후 구현 가이드에서 `first()` 또는 `get(0)`에 의존하지 않도록 합니다.
